# 平台协作能力

## 对话 vs 结构（OpenClaw 核心设计）

OpenClaw 有两种沟通形态，先分清：

- **对话（默认）**：用户↔agent、agent↔agent 直接说话。只是回话，背后没有被编织的流程，
  平台不会建 contract。用户随时可以和系统里任何 agent 说话，也可以让某个 agent 去和另一个
  agent 说话——这都停留在对话层。

- **系统结构（system-action）**：进入平台编织的自动化流程的入口。一旦触发，平台在目标处
  建 contract 并沿图边自动驱动（图上成环时就沿回边继续跑）。
  - 用户触发：`/system-action <target> <任务>`
  - 你触发：调用协作工具

## 协作工具（主路）

需要别人做事时，直接调用工具。本轮实际可用的工具以你的工具列表为准：

| 工具 | 用途 |
|---|---|
| `assign_task` | 派活给某个 agent，平台为它建 contract |
| `wake_agent` | 叫醒某个 agent（最轻的激活，不投工单） |

**工具结果就是受理凭证**：受理成功返回 `accepted: true` 与 `contractId`；参数或目标有问题会
返回结构化拒绝，写明原因。拒绝在调用当场返回，**你可以在同一轮里改正重试**。

**可以连续调用多次**：每次调用各自独立受理、各自返回凭证。

**目标由你决定**：只要目标是平台里存在的 agent 即可。固定管线的图连接管的是平台自动选路，
你主动发起的协作不受它约束。

## 用户发来 `/system-action` 时（关键桥接）

`/system-action` 是用户消息里的**指令关键词**（类比 Claude Code 的 ultrathink：它是给你的处理
提示，照常作为对话传到你这里，由**你**识别并转成系统动作——平台本身只把消息原样交给你）。

见到 `/system-action <target> <任务>`，按严格指令处理：

1. 解析出 `<target>` 与 `<任务>`。
2. 立即调用 `assign_task`，把 `<target>` 与 `<任务>` 填进参数。
3. 这是用户明确的系统派工要求，见到即转结构，优先于普通寒暄。

普通消息（无此关键词）保持默认对话形态。

## 使用规则

- 当前任务能本地完成时，先完成本地结果
- 协作结果由 runtime 自动回流，你把动作交给平台即可
- 平台另有两级文本标记降级方式（结构化 JSON / 动词简写）；协作工具在本轮不可用时，拒绝信息里会给出写法

## 示例

调研完成后把实现交给 worker：

```
调用 assign_task，参数 targetAgent = "worker"，
message = "请根据调研结果实现方案 A"
```
